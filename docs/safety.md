# Safety design

## M0/M1에서 보장하는 경계

- Electron 창은 `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`로 생성합니다.
- Renderer와 Node 기능은 preload에서 검증된 IPC 메서드로만 연결합니다.
- 개발 서버는 `127.0.0.1`에만 바인딩합니다.
- 새 창 열기와 예상하지 않은 페이지 이동을 차단합니다.
- 사진 확장자와 IPC 입력 구조를 main 프로세스에서 다시 검증합니다.
- 비밀번호, 토큰, 쿠키, 계정 데이터는 수집하거나 로그에 남기지 않습니다.
- 개인 사진은 프로젝트 폴더가 아니라 Electron의 앱 전용 `userData` 폴더에 저장합니다.

## 절대 수행하지 않는 동작

- Codex 강제 종료, `taskkill`, `Stop-Process`, `TerminateProcess`
- Codex 반복 재시작 또는 새 창 반복 생성
- 실패 후 일정 간격의 자동 재시도
- Microsoft Store 패키지나 Codex 설치 파일 수정
- `.codex`, `AGENTS.md`, 채팅, 로그인 데이터 접근 또는 수정
- 다른 테마 프로그램 설치, 호출, 수정
- 외부 네트워크 인터페이스에 포트 공개
- 확인되지 않은 연동 방식을 성공 가능한 기능으로 표시

## M2 읽기 전용 조사 결과

- 공식 문서와 프로세스의 기본 메타데이터만 확인했습니다.
- 실행 중인 프로세스의 명령줄, 메모리, 창 내부 상태에는 접근하지 않았습니다.
- Microsoft Store 패키지와 Codex 설치 파일의 내용은 읽거나 수정하지 않았습니다.
- `.codex`, `AGENTS.md`, 채팅, 로그인 데이터에는 접근하지 않았습니다.
- 발견된 다른 테마 프로그램은 실행하거나 호출하거나 수정하지 않았습니다.

## M5 패키징 경계

- Windows 설치 파일에는 컴파일된 `dist`, `dist-electron`, 실행에 필요한 production 의존성, `package.json`, `LICENSE`만 포함합니다.
- 패키지 검사기는 TypeScript 원본, source map, 사용자 데이터 폴더 이름, 개인 Windows 경로, 토큰과 비밀 키 패턴을 차단합니다.
- GitHub Actions는 설치 파일, blockmap, `SHA256SUMS.txt`만 업로드합니다. 로컬 절대 경로가 들어갈 수 있는 `builder-debug.yml`은 공개 산출물에 포함하지 않습니다.
- 설치는 현재 사용자 범위에서 수행하며 관리자 권한 상승을 허용하지 않습니다.
- 제거 시 앱 전용 데이터를 자동 삭제하지 않습니다. 사용자가 고른 사진과 테마가 예상치 못하게 사라지는 일을 막기 위한 정책입니다.
- 현재 빌드는 코드 서명되지 않았습니다. SmartScreen 경고를 우회하도록 안내하지 않으며, 릴리스에는 서명 상태와 SHA-256 검증 방법을 표시합니다.

## M3 수동 적용 경계

M2 조사에서는 공식 사진 배경 API를 확인하지 못했습니다. 이후 사용자가 비공식 런타임 방식의 위험을 이해하고 M3를 명시적으로 승인해, 다음 제한 아래 loopback CDP 실험을 구현했습니다.

- Frostline Studio는 실행 중인 Codex를 닫지 않습니다. 사용자가 직접 정상 종료해야 다음 단계로 진행합니다.
- Windows 보조 프로그램은 확인한 Codex 패키지 ID로 한 번만 실행하며 종료 API를 포함하지 않습니다.
- CDP는 `--remote-debugging-address=127.0.0.1`과 무작위 포트만 사용합니다.
- 포트 소유 프로세스의 패키지 ID가 앞서 확인한 Codex와 같아야 연결합니다.
- 대상 URL이 정확히 `app://-/index.html`인 page Renderer가 하나일 때만 주입합니다.
- 적용과 검증에는 짧은 타임아웃을 사용하며 실패 후 자동 재시도하지 않습니다.
- 활성 세션의 라이브 갱신은 새 프로세스를 시작하지 않고 같은 target ID와 표식을 다시 확인합니다.
- 라이브 갱신이 한 번 실패하면 이전 정상 화면을 유지하고 연결을 잠급니다. 사용자가 수동 재연결을 눌러야만 다음 시도를 시작합니다.
- 호환성 검사는 화면 구조의 존재와 개수만 반환하며 채팅 문자열, 계정 정보나 파일 내용을 읽지 않습니다.
- 복원은 Frostline Studio가 넣은 고유 표식의 `<style>`만 제거합니다.
- 패키지 파일, 설치 파일, `.codex`, `AGENTS.md`, 로그인·채팅 데이터는 읽거나 수정하지 않습니다.

CDP는 loopback에만 열어도 인증 기능이 없는 로컬 디버깅 인터페이스입니다. 같은 Windows 사용자 권한으로 실행되는 다른 프로그램이 무작위 포트를 알아내면 접근할 가능성이 있으므로, 적용이 끝난 뒤에도 불필요하게 오래 열어 두지 말고 사용을 마치면 Codex를 정상 종료해야 합니다.

## M4 승인 지점

M4 자동 적용은 구현하지 않았습니다. M3가 실제 Codex 버전에서 적용과 복원까지 충분히 검증된 뒤 사용자가 다시 승인해야 합니다.

자동 적용을 구현하게 되면 다음 조건이 모두 필요합니다.

- Windows 로그인 시 보조 프로그램 하나만 시작
- 단일 인스턴스 잠금
- 프로세스 시작 이벤트 우선 사용
- 같은 PID에 최대 한 번 적용
- 짧은 적용 타임아웃
- 첫 실패 후 회로 차단
- 수동 재시도 전까지 추가 시도 금지
- 비상 정지 시 자동 적용과 자동 시작을 함께 해제
